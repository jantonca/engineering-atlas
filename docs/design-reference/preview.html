The idea

A reusable response can save a trip to the origin. Follow the path to see why.

Follow a request

Same resource. Different path.

Simplified edge-cache example. Browser caching, revalidation and other intermediaries are omitted; freshness alone does not guarantee reuse.

02

Two paths. One distinction.

Can the stored response be reused?

A / Fresh cache hit

Reuse the response.

Browser⇄Edge

An eligible response is already available. The edge answers; the origin receives no request.

B / Empty-cache miss

Go to the source.

Browser⇄Edge⇄Origin

The cache has no matching response. The request continues to the origin, then the response returns.

03

The response sets the rules.

Cache-Control
max-age=3600

Fresh for an hour.

A freshness lifetime of 3,600 seconds, measured from response generation. Other reuse rules still apply.

no-cache

Store. Then validate.

Storage is allowed, but successful validation is required before every reuse.

no-store

Do not keep a copy.

Do not store this request or response. This does not delete responses that were stored earlier.

The naming trap: no-cache does not mean “never store”. That is the role of no-store.

Pause & explain

Your turn.

A response has Cache-Control: no-cache. Can the cache keep it? What must happen before it can be reused?

Reveal the reasoning

Yes. It may be stored, but the cache must successfully validate it before reuse. no-store is the directive that prohibits storing this exchange.
